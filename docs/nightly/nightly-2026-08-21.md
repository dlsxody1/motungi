- **문제**: 두루누비 courseList의 `gpxpath` 값을 처음 받아 fetch하는 적재 경로(`fetchTrailStartCoord`)에 호스트/스킴 검증이 없어, `SERVICE_ROLE` 권한으로 매일 1회(pg_cron) 실행되는 Edge Function이 상류(data.go.kr) 데이터 오염 시 임의 URL로 fetch할 수 있는 blind SSRF primitive였다. 읽기 경로(`apps/web/src/app/api/trail-route/route.ts`)는 이미 `protocol==="https:" && hostname==="www.durunubi.kr"` 화이트리스트로 막혀 있었다.
- **범위 경계**: `supabase/functions/ingest/index.ts`(가드 삽입) + `packages/core/src/adapters/ingest-fetch.ts`(공유 순수 함수 `isAllowedGpxUrl` 신설) + `ingest-fetch.test.ts`(단위 테스트 6건). 계획된 scope(`supabase/functions/ingest/index.ts`)보다 `packages/core` 쪽에 파일이 하나 더 늘었는데, 이는 M-026(`isCronAuthorized`)이 이미 확립한 패턴 — index.ts 상단이 `Deno.env.get(...)!`로 즉시 던지는 모듈이라 그 파일의 함수를 직접 export해 테스트할 수 없고, 부작용 없는 leaf 모듈(`ingest-fetch.ts`)에 순수 함수로 옮겨야 Deno·vitest 양쪽에서 안전하게 재사용·테스트된다는 이미 검증된 이유를 그대로 따른 것이다. `apps/web/src/app/api/trail-route/route.ts`는 참고만 하고 손대지 않았다(이미 방어돼 있음).
- **구현**: `isAllowedGpxUrl(url): url is string`이 `new URL(url)` 파싱 후 `protocol==="https:" && hostname==="www.durunubi.kr"`를 검증(파싱 실패·null·undefined·빈 문자열은 전부 false). `fetchTrailStartCoord`가 `fetch` 호출 전에 `if (!isAllowedGpxUrl(gpxUrl)) return null;`로 가드 — 실패 시 기존과 동일하게 좌표만 비워지고 적재 전체는 막지 않는다.
- **테스트**: https+정확한 호스트 통과 / http 거부 / 다른 호스트 거부(`evil.example.com`) / 서브도메인 불일치 거부(`api.durunubi.kr`, `internal.durunubi.kr.evil.com`처럼 접두어·접미어로 호스트를 흉내내는 시도 포함) / 깨진 URL 거부 / null·undefined·빈 문자열 거부. 6건 전부 통과.
- **done_when 3번째 항목에 대한 정직한 기록**: 요구사항 문구는 "fetch가 호출되지 않음을 검증하는 테스트"였다. 실제로 작성한 것은 그 가드로 쓰이는 순수 함수 `isAllowedGpxUrl`의 단위 테스트이지, `fetchTrailStartCoord` 자체에 대한 spy/통합 테스트가 아니다. `index.ts`를 직접 import하는 Deno 테스트를 새로 만들지 않은 이유는 M-036이 이미 문서화한 것과 동일하다 — 모듈 최상단이 즉시 던지는 non-null assertion들 때문에 production 코드를 추가로 바꾸지 않는 한 import 자체가 안 되고, 이 환경엔 `deno` 바이너리도 없어 실행 검증도 불가능하다. 논리적으로는 동등하다(early return 이후 `fetch` 라인에 도달할 경로가 없음을 코드 읽기로 확인·qa가 재확인) — 그러나 글자 그대로의 "그 함수를 spy로 잡아 검증"은 아니므로 부분 충족으로 기록한다.
