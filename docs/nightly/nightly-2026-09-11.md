  고정하는 방식을 썼다(두 테스트 파일은 별도 vitest 프로세스로 서로 import하지 않으므로
  진짜 크로스파일 비교는 아님, 같은 계약을 각자 증명하는 구조).
- **`useOpportunity` error 상태 테스트 2개**(fix round 추가분) — web: fetch reject →
  `isError` 경로. mobile: `fetchOpportunityById`가 `{data:null, status:"error"}`로
  resolve하는 경로. 플랫폼별 실제 에러 발생 경로 차이를 반영해 테스트 방식도 따로 썼다.
- **누락 보강 2건**: `useEnsureCatalog` mobile의 empty passthrough 테스트(web엔 있었는데
  mobile엔 없었음), `useSavedOpportunities` web의 mid-flight loading 단언(mobile엔
  있었는데 web엔 없었음).
- **인라인 주석 다수**: `useOpportunity`의 시그니처 비대칭(web `initial?` 2번째 인자 vs
  mobile 없음, SSR 선시딩 목적), `useSavedOpportunities`의 시그니처 비대칭(mobile은
  `(savedIds, catalog)` 인자, web은 스토어 직접 구독), `useTrailRoute`/`useWhyReasons`
  4개 파일의 "로딩 상태가 반환 shape에서 관측 불가능함" 설계 사실 — 전부 버그가 아니라
  의도된 차이임을 코드에 남겼다.
